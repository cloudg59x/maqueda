Test page. Every button sends a real request to the wallet; approve/setApprovalForAll are real transactions on the selected chain.

Inputs

1. Wallet

Connection, chain id and chain switching (EIP-1193 / EIP-3085 / EIP-3326).

2. EIP-7702 delegation (via EIP-5792)

A dApp cannot request a 7702 authorization directly; wallets whitelist delegation contracts. The standard path is wallet_sendCalls: a wallet with atomic: ready prompts the EOA → smart account upgrade. The raw type-4 button shows what happens when a dApp tries anyway.

3. ERC-20 approve()

Real transactions on the selected token contract. approve(spender, amount) selector 0x095ea7b3.

4. setApprovalForAll()

Selector 0xa22cb465, identical for ERC-721 and ERC-1155. Uses the NFT contract input (dummy by default: the wallet still decodes and warns).

5. EIP-2612 permit via eth_signTypedData_v4

Off-chain signatures, no gas. Nonce and token name are read on-chain first so the signature is valid. USDC uses domain version "2".

For comparison of the wallet's prompts.
